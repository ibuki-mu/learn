# P-A — 待办事项管理器（纯 Java 命令行）

> 归属：[`ROADMAP.md`](../ROADMAP.md) 第一阶段。时间盒 **3 周**，预估 60 小时。
> 红线：**禁用 Spring / MyBatis / 任何持久化或集合库**。集合、异常体系、序列化必须手写。
> 规则：核心代码由用户自己写；AI 只做评审、出题、解释、样板。见 [`AGENTS.md`](../AGENTS.md) 规则 11–13。

## 1. 目标

用纯 Java 做一个真正能每天用的命令行待办工具，并在此过程中**亲手实现**集合与序列化底层，把「会用 API」变成「知道 API 里发生了什么」。

## 2. 功能范围

**必须有（不做完不算交付）**

- [ ] 任务增 / 删 / 改 / 查
- [ ] 字段：`id`、`title`、`priority`(HIGH/MEDIUM/LOW)、`dueDate`(可空)、`completed`、`createdAt`
- [ ] 列表支持过滤与搜索：按优先级过滤、按关键词搜索标题
- [ ] 列表支持排序：截止日期升序、优先级降序
- [ ] 标记完成 / 取消完成
- [ ] 列表分页显示
- [ ] 退出时自动保存到本地文件；启动时自动加载
- [ ] 业务异常体系
- [ ] 数据损坏或文件缺失时的**优雅降级**（不崩溃、给出可读提示）

**明确不做（本阶段砍掉）**

- 多用户、并发、网络、GUI、数据库、JSON、Spring。

## 3. 必须手写的部分（AI 不得代写）

| # | 交付物 | 具体要求 |
|---|---|---|
| 1 | `MyArrayList<E>` | 内部数组；容量按 **2 倍**扩容；实现增删改查、`size`，不用 `java.util.*` 集合 |
| 2 | `MyHashMap<K,V>` | 数组 + 链表；容量始终为 2 的幂；负载因子 **0.75**；2 倍扩容并 rehash |
| 3 | 树化阈值 | 单桶链表长度 **≥ 8 且 容量 ≥ 64** 时桶内转树；树节点数降到 **6** 时退化回链表。树可用简化 BST，**重点是把阈值与触发条件跑出来并用测试证明** |
| 4 | 异常体系 | 基类 `TodoException`；`TodoNotFoundException`(unchecked)；`InvalidTodoFormatException`(checked)。**必须能解释为什么这样分** |
| 5 | 文件格式与序列化 | 自定义 `|` 分隔文本格式（理由见 §4）；自己设计字段转义；自己写读写 |
| 6 | CLI 参数解析与业务逻辑 | 不引第三方 CLI 库 |
| 7 | 测试用例设计 | 测试代码可让 AI 补样板，但**用例本身（测什么、边界在哪、预期值多少）由你设计** |

## 4. 已定技术决策（不再讨论）

- **存储格式用自定义 `|` 分隔文本，不用 JSON。**
  理由：① 文件格式设计属于「必须自己来」的架构范畴（`AGENTS.md` 规则 11）；② JSON 手写解析器会大幅超出时间盒；③ 自研格式无 parser 兼容性风险，能稳定验收。字段顺序 `id|priority|completed|dueDate|createdAt|title`，`title` 中的 `|`、`\`、换行需转义。
- **构建用 Maven**（`maven.compiler.release=21`），依赖按需引入：M1 仅 JUnit 5；Mockito 与覆盖率插件留到 M2/M3。不引 Lombok、Jackson、Guava、Commons。
- **不做并发**。线程安全不是本项目目标，留到第一阶段后段的并发专题。

## 5. 里程碑与时间盒

| 周 | 里程碑 | 交付 | 工时 |
|---|---|---|---|
| W1 | **M1 内存版能跑** | `MyArrayList` + `MyHashMap`（含阈值逻辑）+ 领域模型 + 内存 CRUD + 基础 CLI + 集合单测 | 20h |
| W2 | **M2 能持久化** | 异常体系 + 文件格式编解码（含转义）+ 自动存取 + 过滤/搜索/排序 + 边界单测 | 20h |
| W3 | **M3 能交付** | 分页 + README + 技术复盘 + 补齐测试 + 自查清单打勾 + 最终验收演示 | 20h |

**超时处理**：只砍需求（如砍分页、砍排序维度），**不砍**手写集合、异常体系、测试。时间盒不可延长。

## 6. 每周固定安排

- **无 AI 日（W1–W3 各一天）**：手写集合与序列化核心，不看任何 AI 输出。
- **原理时间**：读 `java.util.ArrayList` / `HashMap` 源码，与自己实现对照，把差异写进复盘。
- **AI 代码审查**：W2 结束、W3 结束各一次，**必须由独立子代理执行**（不得自审），产出问题清单由你逐条裁决。
- **模拟面试**：W3 一次，题目围绕 HashMap 阈值、异常设计、为什么不用 JSON。
- **复盘**：每周一篇，W3 收官篇进 `README.md` 的设计说明。

## 7. AI 使用边界（本项目）

| 可以交给 AI | 必须自己来 |
|---|---|
| Maven `pom.xml` 配置、surefire 配置 | 集合实现、扩容与 rehash、阈值逻辑 |
| JUnit 5 断言样板、测试类骨架 | 测什么、边界在哪、预期值 |
| 解释 `HashMap` 源码、报错信息、术语 | 异常体系设计、文件格式与转义设计 |
| README 排版、结构建议 | 核心业务逻辑、CLI 解析逻辑 |
| 独立评审代码、出题 | 对每条 AI 建议做裁决并承担结果 |

**硬性流程**：AI 给的东西必须自己敲、跑、改。卡壳先定位 30 分钟再问。

## 9. 验收标准（不可协商）

必须在**不看代码**的情况下口头完成：

1. 画并讲清 `MyHashMap` 结构：冲突如何解决、何时转树、为何退化阈值是 6 而非 8
2. 讲清 `MyArrayList` 扩容为什么选 2 倍，均摊代价怎么算
3. 说明异常体系划分，以及 `InvalidTodoFormatException` 为什么必须是 checked
4. 演示：跑起来 → 添加 → 过滤 → 排序 → 退出 → 重启数据还在
5. 演示：手动破坏数据文件 → 程序优雅降级
6. `mvn test` 全绿并展示覆盖率报告
7. `git log` 呈现清晰迭代，展示冲突解决记录

**交付物**：可运行程序 + 全绿测试 + `README.md`（含设计取舍）+ 3 篇技术复盘 + 验收演示记录。
